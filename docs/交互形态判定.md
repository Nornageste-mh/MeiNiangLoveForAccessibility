# 交互形态判定（男娘恋爱物语 · 无障碍补丁 0.1.1.0）

判定人：Lead（自动化 + 反编译证据）　判定日期：2026-11-16
依据：`Framework/docs/交互形态纪律.md`（第 0 条纪律）、`Framework/docs/操作逻辑公约.md`

## 一、判定结论：A 类（游戏本身有完整键盘操作）

**判据**：不装补丁时，游戏全流程（标题 → 剧情 → 选项 → 设置 → 存读档 → 确认 → 退出）
都可以用方向键 + 回车 + Esc 完成。补丁只做朗读，不接管输入、不改键位、不加模式。

**证据**：

- [实测] 不装补丁，用 Ren'Py 自带测试框架在游戏副本上纯键盘走到主菜单、开始游戏、推进
  台词（`evidence/run-*` 的基线用例，回滚后 1219 文件 SHA256 与原始一致）。
- [文件] 反编译确认所有界面控件都有键盘可聚焦的 `button` / `imagebutton` / `bar`，
  没有只支持鼠标的界面（`work/game-scripts/REPORT.md` §界面可读性核心表）。
- [文件] 游戏自带 `config.keymap` 保留 `focus_left/right/up/down`、`button_select`、
  `dismiss`、`game_menu`；只清空了 `self_voicing`（alt+V）并去掉了 rollback 的鼠标键。

**A 类下的补丁边界**：只接管"朗读出口"（`config.tts_function`）与"焦点朗读补充"
（`renpy.display.tts.displayable` / `Button._tts_all` / `SayBehavior._tts_all`），
另外按公约加 1 个朗读侧单键（Backspace 重读）、1 个朗读侧组合键（Alt+Shift+F9 换后端），
以及选项界面的 1–9（见 `操作约定.md` 第四节，已登记差异）。

## 二、逐界面清点

| 界面 | 不装补丁能否纯键盘完成 | 原生键位/焦点机制 | 缺什么（读屏视角） | 补法 | 游戏自身入口 |
|---|---|---|---|---|---|
| 标题菜单 `main_menu` | 能（↑↓ + 回车） | `focus_ordered` 顺序焦点 | 按钮是 imagebutton + foreground Text，引擎读空串/只读动作 alt | `Button._tts_all` 补上按钮画出来的文字 | `screens.rpy:172 title_button`、`screens.rpy:188 main_menu` |
| 剧情 `say` | 能（回车/空格推进） | `SayBehavior` 可聚焦 + dismiss | 引擎整屏读会把日期装饰"2023年"、快进标记一起念 | `SayBehavior._tts_all` 只读台词本体 + say 屏幕 `who` | `SayBehavior` / `screen say` |
| 剧情选项 `choice` | 能（↑↓ + 回车） | 选项按钮可聚焦 | 选项 text 在 foreground，引擎读不到 | 同上按钮补偿 + 朗读时加"1、2、"编号 | `screens/common.rpy:90 screen choice` |
| 设置 `preferences` | 能（↑↓ 浏览、←→ 调值） | radio 按钮 / bar 可聚焦 | 单选项读不到；滑条只读 increase/decrease 英文 | 按钮补偿 + 英文状态词中文化（`selected/bar/activate…`） | `screens/preferences.rpy:59` |
| 存读档 `save/load` | 能 | 槽位按钮 + 翻页 | 槽位文字在无 action 的 button 里，可点击按钮无文字 | 按钮补偿（向上找容器文字） | `screens/save.rpy` |
| 确认框 `confirm` | 能 | textbutton | 基本可读（引擎原生） | 不需要 | `renpy/common/00layout` |
| 快捷栏 `quick_menu` | 能 | 8 个 imagebutton | 读不到文字 | 按钮补偿 | `screens/quick_menu.rpy:22-57` |
| 游戏内菜单侧栏 `game_menu` | 能 | imagebutton | 读不到文字 | 按钮补偿 | `screens/game_menu.rpy:10-27` |
| 输入框（存档页数字跳页） | 能（键盘输入） | `renpy.display.behavior.Input` | 自绘输入框文字可读性未逐项核对 | Backspace 让位给 Input；不强行补 | `screens/save.rpy:24-60` |
| 画廊 `gallery` / 音乐室 / 语音收藏 | 能 | imagebutton | 按钮文字读不到 | 按钮补偿（通用） | `screens/gallery.rpy` 等 |
| 真结局后广告菜单 | 能 | 可点按钮 | 会 OpenURL 跳商店，盲人误触风险 | 只朗读，不改按钮行为；在测试文档标注 | 结局脚本 |

## 四、验收 7 问

1. 纯键盘能完成主流程？**能**（原版就能；补丁未改键位）。[实测] 自动化用例纯键盘走通标题/设置/读档/开始游戏/选项/退出确认。
2. 当前朗读项 = 游戏当前选中项？**是**（读的就是 `renpy.display.focus.get_focused()`）。[实测]
3. 关掉补丁行为不变？**是**（删目录即还原；回滚后 1219 文件 SHA256 一致）。[实测]
4. 有没有新增可见物？**没有**。[文件] 补丁只加 `.rpy` 逻辑，不 show screen、不画 overlay。
5. 玩家要不要背补丁专属操作？**不要**（只有公约里的重读/换后端/数字选项）。[文件]
6. 朗读是否由游戏事件触发？**是**（`set_focused` → `tts.displayable`；say/menu 由引擎交互驱动）。[实测]
7. 不满足的项是否已登记？**是**（见第五节遗留）。

## 五、遗留缺陷 / 待实机确认

| 编号 | 界面/场景 | 缺什么 | 为什么补不上 | 玩家感知 | 计划 |
|---|---|---|---|---|---|
| L-01 | 标题菜单首次出现 | 引擎整屏朗读一次（含版权行） | 引擎 `displayable(None)` 读场景根的行为，属引擎原生 | 会先听一长串菜单文字，之后逐项正常 | 保留（引擎行为）；文档说明 |
| L-02 | 剧情界面 | 每句前偶有一次"2023年"日期装饰朗读 | say 屏幕上的日期 Text 在交互开始时被整屏读一次 | 多听两三个字 | 观察实机是否可接受；如不可接受，考虑交互开始时的焦点抑制 |
| L-03 | 设置滑条 | 只念"增加/减少"，数值本身无朗读 | 引擎 Bar 的 `_tts_all` 不带数值 | 不知道音量具体百分比 | 后续可加"当前值"补充朗读（需确认不违反 A 类） |
| L-04 | 存档页数字跳页输入框 | 输入内容与提示未逐项核对 | 自绘 input，需实机确认 | 可能读不到输入框提示 | 实机测试确认后补 |
| L-05 | 画廊/音乐室/语音收藏 | 只做了通用按钮补偿，未逐项核对 | 无头测试难以覆盖全部子界面 | 可能个别按钮仍静默 | 手测清单覆盖 |
| L-06 | NVDA 真机发声 | 自动化只能断言"文本到达朗读出口"，无法证明 NVDA 真的发声 | 测试机无 NVDA；NVDA 读音需人耳 | 需要用户实机确认 | 测试文档第 2 节 |
| L-08 | 争渡真机发声 | 只核对了 `GetSpeakState()` 判据，未在游戏里确认"听到的是争渡的声音" | 判据是接口层事实，发声需人耳 | 需要用户实机确认 | 测试文档第 1.6 节 |
| L-07 | 快进 / 限时选择 | 无头下快进会崩引擎（0xC0000005），未自动化 | 无头 sw 渲染器限制，与补丁无关（无模组基线同样崩） | 快进时补丁停止补念（代码已处理） | 实机手测 |
